Runs Assistant

A MIDI plug-in (VST3 / CLAP / AU) that turns two notes played together into a realistic scale run - shaped in time and accented to the beat.

The one-sentence version Arm the engine, play two notes at once (any order), and Runs Assistant swallows them and plays a run between the two pitches, locked to your DAW's grid, over a chosen number of beats.

1. What it does

Runs Assistant is MIDI middleware: it sits on a track before the virtual instrument and rewrites what reaches it. It produces no sound of its own. Realism comes from two ideas:

  • Shape in time (Curve) - run notes do not arrive at metronomic spacing. The start and end of the run spread out while the middle rushes through: slow, quick, slow. One slider sets how strong that shape is; at 0% the sweep is perfectly even.
  • Metric velocity emphasis (Accent) - notes landing on a beat play louder, with downbeats strongest, scaled by how close each note falls to the grid line. At 0% every note is the same loudness.

On top of that, each note's velocity is a fade between the two trigger notes' velocities, optionally swelled or tapered by the Arc control - so a run can start fff and end ppp just by how you played the pair.

Typical uses: scalar runs and flourishes in orchestral mock-ups, fast licks for lead instruments, harp/guitar glissando-style lines that stay in key and on the beat.

2. Install & routing

  1. Copy the plug-in bundles into your VST3 / CLAP / AU folders (or run the installer provided with the release).
  2. Rescan plugins in your DAW.
  3. Insert Runs Assistant on a MIDI track as the first plug-in, ahead of the instrument that should play the run (e.g. Runs Assistant → sampler → mixer).
  4. Make sure the instrument receives MIDI from the track as usual. Runs Assistant passes everything it does not consume straight through, so the rest of your playing is unaffected.
FormatNotes
VST3Exposed as an instrument with one silent stereo bus (a host category requirement). Audio passes through untouched; only MIDI matters.
CLAPA note-effect: insert it before your instrument in the chain.
AU (macOS)Available both as a MIDI-controlled effect (aumf) and for the MIDI FX slot (aumi).
Tip Primary validation host is REAPER. Other hosts work best-effort; if a host does not forward MIDI between plug-ins on a track, the engine will simply look silent.

3. Quick start

  1. Insert Runs Assistant before your instrument.
  2. Leave the engine at Up (the default).
  3. Pick a scale: Tonic + Mode (defaults: C, Major).
  4. Set Beats to 4 and Density to 5 notes/beat - that makes a 20-note run over 4 beats.
  5. Press play (or stay stopped - both work, see 5), then play two notes together, for example C4 and C5. The pair disappears and a 20-note C major run from C4 to C5 fires, aligned to the next beat.
  6. Release either trigger note early to cut the run; play around with Curve and Accent while you listen.

4. Engine states: Off / Up / Down

The three buttons in the title row are the engine switch. Exactly one is active. The engine boots in Off and the state is saved with your project.

StateBehaviour
OffFull pass-through. Every note, CC, program change and keyswitch goes out exactly as it came in - Runs Assistant does nothing. Use this as your bypass.
UpTwo notes together fire a run climbing from the lower pitch to the higher pitch.
DownThe same, but descending: from the higher pitch to the lower one.

The switch can be driven three ways (choose in Settings):

SourceOffUpDownDefault
CC0 - 4041 - 7980 - 127CC87
Notes (keyswitch)C0C#0D0opt-in
Program change012opt-in
  • The GUI buttons, the MIDI source and host automation all control the same state and mirror each other.
  • Changing the engine while a run is active cuts the run immediately.
  • Engine-off handoff: a note you are still holding while the engine is Off becomes that channel's pending note when you switch to Up/Down - the next note you play completes the pair right there, without needing to re-strike.

5. Trigger pairs, singles and jabs

How a pair fires

  • While the engine is Up/Down, the first note you press is held back (pending) - nothing is sent yet.
  • If a second, different-pitch note arrives while the first is still held, the pair is complete: both notes are consumed and the run fires at that instant, with its start aligned forward to the next beat.
  • The lower pitch of the pair is the start, the higher is the target; the engine direction decides which end the run begins from. The two played velocities become the run's first and last velocity.
  • If the trigger lands within about 2 ms after a beat line, it counts as being on that line (human anticipation tolerance) and the run starts there.

Single notes (melody still works)

  • If you press a note and release it again before playing anything else, it is played late - it sounds as a short note (from the release moment), so your melody is never swallowed. The debug overlay counts these as late singles.
  • Pressing the same pitch twice never makes a pair; both notes play normally.
  • Once a note is sounding and a second melodic note arrives, it also passes straight through - the pair window is strictly "both notes still held and unheard".
  • Three-note (and bigger) chords: the extra notes pass through.
Worth knowing Very fast legato playing while the engine is on can occasionally form an accidental pair (two notes pressed before the first is released). That is inherent to the trigger design; switch the engine to Off for straight melodic playing.

6. Cutting a run

One run at a time; triggers during an active run are ignored. A running run ends immediately - already-sounding notes stop at that sample, scheduled notes are dropped - when any of these happens:

  • you release either of the two trigger notes,
  • the engine state changes (GUI button, engine CC/keyswitch/PC, or host automation),
  • the transport jumps: loop wrap, click-back or a seek,
  • all-notes-off (CC 123) arrives - which also passes through to the instrument,
  • playback starts or stops (the scheduling grid changes meaning).
The final note holds The run's target note is not stopped by the beat count. It keeps ringing until you release a trigger note (or another cut happens). So with Beats = 4 and the pair held for 8 beats, the run sweeps across beats 1-4 and the last note rings on through beat 8.

7. Scale: Tonic, Mode and the tick grid

  • Tonic - C through B, the root everything is measured from.
  • Mode - Major (Ionian), Dorian, Phrygian, Lydian, Mixolydian, Aeolian (Natural Minor), Locrian, Harmonic Minor, Melodic Minor (ascending), Whole Tone, Octatonic (whole-half), Octatonic (half-whole), Major Pentatonic, Minor Pentatonic, Blues, Chromatic, Custom.
  • 12 pitch-class ticks - always visible. Choosing a tonic + mode ticks them for you. Ticking or un-ticking a box by hand switches the Mode to Custom and keeps exactly your tick set.

Runs can only contain scale tones. When the two trigger pitches are not scale notes, each endpoint snaps inward to the nearest one (the span never grows). If snapping makes the two notes collapse onto the same pitch, there is no run: both notes simply play through as ordinary notes.

Tip Chromatic is just "all twelve ticked". For a whole-tone flourish, pick Whole Tone mode; for a blues lick, Blues.

8. Beats, Density and Curve (the run's shape)

ControlRange / defaultWhat it does
Beats1..16, default 4How long the run takes to sweep from first note to target, in host beats. This is the run's time span; the held trigger notes decide when the final note ends.
Density1..16 notes/beat, default 5Note count = round(Density x Beats). Default: 5 x 4 = 20 notes.
Curve0..100%, default 22Timing shape. 0% = even, metronomic spacing. Higher = the run starts deliberately spread out, races through the middle, and settles at the end (slow, quick, slow).

Grid lock and transport

  • Playing: all onsets are scheduled in host beat positions, so they follow the DAW grid and tempo changes exactly. The run starts on the next whole beat after the trigger.
  • Stopped (or no timing info): a virtual grid at the last known tempo (default 120 bpm) runs from the trigger moment. You can audition runs without playing the transport.
  • Time signature is read from the host (default 4/4) so bar-line accents land where you expect.

Note count effects

  • Under-filled (fewer notes than scale degrees in the span): the climb is compressed proportionally across the run - leaps are spread out rather than dumped at the end.
  • Over-filled (more notes than degrees): the run has to double back; the Walk mode decides how.

9. Accent, Arc and Overlap (the run's feel)

ControlRange / defaultWhat it does
Accent0..100%, default 41Metric emphasis: notes close to a beat line play louder; downbeats get the strongest push, other beats a lighter one. 0% = flat, 100% = strong groove.
Arc-100%..+100%, default +15A final swell or taper across the run. Negative fades the run out, positive fades it in, 0% is neutral. Applied on top of the start→target velocity fade.
OverlapOff / On, default OnOn: each note is held slightly past the next note-on, so instruments that engage legato mode by detecting overlapping notes will trigger it. Off: every note stops before the next begins.

Per note: velocity = start→target fade x Arc x Accent, clamped to 1..127.

Tip Play the pair with very different velocities (e.g. first note fff, second pp) to get the dramatic fade; use Arc when you want a swell that has nothing to do with how you played the pair.

10. Walk: Fold vs Zig-zag

When the requested note count exceeds the scale degrees available in the span, the walk has to repeat material. The choice is live at trigger time.

ModeBehaviour
FoldThe run climbs to the edge of the span and bounces back, like a reflection. Both endpoints are always visited exactly.
Zig-zag (default)The run stays mostly monotonic, inserting single backward steps at evenly spread positions, so the overall climb reads as a steady ascent with small kickbacks.
  • Consecutive notes never repeat a pitch - a backward step is exactly one scale tone.
  • The first note is always the run's start pitch and the last is always the target, whatever the walk does in between.
  • With Zig-zag, an odd step count can require dropping one note (the run comes out one note shorter than Density x Beats); the debug overlay counts these parity drops.

11. Curve shape preview

The square graph under the Walk/Overlap row draws the run the engine would play:

  • Left → right is time through the run; bottom → top is pitch progress (Engine Down mirrors it: top-left to bottom-right; Engine Off shows the up shape).
  • One dot per run note, sitting on the curve at its exact onset - so the dots visibly crowd the middle and spread at the rims as you raise Curve.
  • The faint straight diagonal is the 0% (even) reference. Higher Curve bends the line away from it.
  • It follows Curve, Beats and Density live. It is an illustration only - it is not interactive and shows no playhead.

12. Humanize and Seed

Humanize gives every run note a small, seeded velocity deflection and timing jitter so repeated runs do not sound machine-perfect. It is a host parameter (Off by default), and the seed and strengths travel with your project.

ControlRange / defaultWhat it does
HumanizeOff / On, default OffMaster switch. Off, the run is exactly deterministic no matter what the other fields hold.
Seed0..999999, default 00 = a fresh seed every run. Any other value pins the pattern: same seed + same settings = the same run, every time (including offline renders).
H.vel0..50%, default 10Velocity deflection strength - up to +/- the set percent per note.
H.time0..50 ms, default 8Maximum timing deviation per note, converted to beats at the current tempo.
  • Double-click either strength slider to reset it to its default.
  • Timing jitter never inverts note order, never moves a note before the run start or past its end, and never touches the run's grid-locked start, the scale snapping or the walk - only the notes inside the run move.
  • The accent model still judges each note against its un-jittered grid position, so the metric emphasis stays honest.
  • Neither control is MIDI CC-mappable (nor is Overlap); they are driven from the panel, host automation (Humanize/Seed) or the saved state.
Pinning a run you liked With Seed 0, turn on the debug overlay - it prints the seed each run actually used. Type that number into the Seed field and the identical sway replays every time. (Press Return or click away to commit.)

13. MIDI export (drag to the arrange window)

The Midi Export row renders one complete run from your current settings and hands it to the OS as a file you can drop straight into your DAW:

  1. Choose Start and Target notes (C1..C8, defaults C4/C5) and each note's velocity (defaults 100/90).
  2. Press, hold and drag off the Drag MIDI button - the file appears under the cursor and drops into the arrange window. (A plain click only flashes a hint; the drag is what does the work.)
  • Direction follows the endpoints: lower→higher renders an Up run, higher→lower a Down run. Start carries the first velocity, Target the last.
  • The file starts at beat 0 with 480 ticks per quarter, carries the current tempo and time signature (120 bpm / 4/4 if the host reported none) and a track name. Drop it on a bar line and the accents land on bar lines.
  • The held final note is closed with an explicit note-off one beat after the last onset.
  • If Start or Target is outside the current scale a red warning line appears naming the note: the render still snaps it inward (like live playing). It only refuses when the pair degenerates - a short reason then flashes on the button instead.
  • Export inputs are session-only: they are not parameters, not CC-mapped and not saved with the project.

14. Copy & Paste between instances

The bottom row moves the whole state - engine, scale (tonic, mode, ticks), Beats, Density, Curve, Accent, Arc, Walk, Overlap, Humanize, Seed and all the settings - through the system clipboard as JSON text.

  • Copy to Clipboard flushes the last held control values first, so the text is always current. The button flashes Copied.
  • Paste from Clipboard applies a Runs Assistant payload; out-of-range values are clamped and missing fields keep their current values. Anything that is not a Runs Assistant preset is rejected and changes nothing. Flashes Pasted or the reason.
  • This is the only preset mechanism in v1 - there are no preset files. Save state in the project itself, or keep JSON snippets in a text editor.

15. Settings dialog

Open with the Settings button in the title row (Esc closes it). Everything here is saved in the project state (not exposed as host parameters).

Engine switch source

  • Engine switch source: Notes / CC / PC.
  • Engine CC number (CC mode, default 87), or the three keyswitch notes (Off/Up/Down, default C0/C#0/D0), or the three program changes (default 0/1/2).

Per-parameter CC bindings

Eight rows - Beats, Density, Curve, Accent, Arc, Tonic, Mode, Walk - each takes a CC number 0..127 or none. Defaults are CC88..CC95 in that order. Duplicate assignments are refused with a red warning on the row (the engine CC counts too). Incoming bound CCs are absorbed while the engine is on and mirrored live to the GUI; with the engine Off they pass through and the bindings are inert. Overlap, Humanize, Seed and the H.vel / H.time sliders are not CC-mappable.

Tuning (raw values)

FieldDefaultMeaning
Alignment epsilon (ms)2A trigger landing this close after a beat line counts as being on it.
Gate fraction0.6Each interior note's length as a share of the gap to the next note (also the Overlap overhang share).
Downbeat weight1.0Accent push on bar lines.
Mid-bar beat weight0.75Accent push on other beats.

These are tuning knobs for the adventurous - change them by ear, they travel with the project. Reset to defaults restores factory parameters, CC bindings, tuning and engine source settings (not undoable).

No undo v1 has no undo manager: edits apply immediately. Copy to Clipboard before experimenting if you want a way back.

17. Debug overlay

The Debug overlay checkbox in the bottom row opens a status readout:

LineContents
1Engine state, current pending note (if one is held back), and internal engine-switch diagnostics.
2Run progress: notes emitted / total, and the last emitted pitch and velocity.
3Counters: parity drops (Zig-zag note-count adjustments), late singles (melody notes released before pairing, played late), cuts.
4Input event counts and any drops (overflow / mirror drops).
5Playhead beat, tempo, and - while Humanize is on - the seed the last run used.

18. Host automation

All twelve parameters are host-automatable and named as on the panel:

Engine (Off/Up/Down) Beats Density Curve Accent Arc Tonic Mode Walk Overlap Humanize Seed

Settings (engine source, CC bindings, tuning constants, humanize strengths) are project state but deliberately not host parameters. Changing the engine from the GUI marks the project modified, so your engine state is always saved.

19. Saving and state

  • Everything lives in the project/chunk: parameters, scale ticks, CC bindings, tuning, engine state and window size. Old projects from earlier schema versions load with the new fields at their defaults; corrupt or truncated data is rejected and your current state is kept.
  • Runtime state is never saved: pending notes, an active run and the resolved humanize seed are all live-only. (The Seed parameter is saved; the seed a particular run happened to draw is not - read it off the overlay to pin it.)
  • There are no preset files in v1; use Copy/Paste (section 14) to move settings.
  • Pending CC tweaks are flushed into the state before it is written, so saving always captures the last held control values even with the window closed.

21. FAQ & tips

Nothing happens when I play two notes.

Check the engine is Up or Down (not Off), that the two notes are different pitches and both still held when the second arrives, and that both fall (after snapping) on different scale degrees. The overlay's pending note field shows whether the first note was registered.

The run plays but sounds late / early against the beat.

The run always starts on the next whole beat after the trigger; the trigger itself is consumed. If you trigger slightly before the beat, the run waits for it (up to the 2 ms alignment epsilon past the line). Nudge your playing, or lower the alignment epsilon in Settings if your timing is consistently late.

My melody notes get cut short while the engine is on.

Those are late singles - a note released before a pair formed. Play a bit more legato-separated, or switch the engine to Off for straight melodic lines (a held note survives the switch back to On and can still seed a pair).

How do I bypass without losing my settings?

Engine Off is the bypass - full pass-through, state intact. You can also automate the Engine parameter or send the engine CC.

Can I run two runs at once?

No - one run at a time (v1). Triggers during an active run are ignored; per-channel runs are a v2 item.

The run feels too perfect / too random.

Leave Humanize off for a deterministic run. On, keep H.vel near 10% and H.time near 8 ms for a subtle sway; push them toward 50 for a loose, human feel. Pin a Seed once you like the character.

Does it work when the transport is stopped?

Yes - a virtual grid at the last known tempo (120 bpm default) starts at the trigger, so you can audition settings with the transport parked.

Why does the last note keep ringing past Beats?

By design: Beats sets the sweep span; the held target note ends when you release a trigger note (see section 6).

Shortcut keys.

None are special, except Esc closing Settings. Seed fields commit on Return or focus loss; double-click the H.vel/H.time sliders to reset them.
